# Как передать исследование

Для явно запрошенного расширенного исследования Codex доступен отдельный профиль
`codex-available-8x-v1`: 8 моделей, 46 сочетаний, 1380 основных + 40 пилотных +
48 контрольных наблюдений. [Схема 1.1 и сохранение неуспешных попыток](docs/EXTENDED_CAMPAIGN.md).
Стандартный семимодельный профиль остаётся прежним; расширенный выбирается явно.

**Обязательный полный протокол: 7 моделей × 5 effort × 30 задач = 1050 основных результатов, плюс 35 пилотных и 42 контрольных. Один блок из 30 задач — только 1/35 основной матрицы.** [Инструкция запуска](docs/RUN_FULL_STUDY.md), [конфигурация](Easy-Bench/campaign.json). Неполные данные сохраняйте как локальный checkpoint; отправка и доверенная проверка PR требуют полного покрытия.

Исследование принимается отдельным pull request, содержащим только новый файл:

```text
Easy-Bench/studies/<study-id>/study.json
```

Создайте его командами `study create` и `study record` из [README](README.md). Используйте уникальный ID из строчных латинских букв, цифр и дефисов. Если файл уже принят, новые измерения отправляйте с новым ID; старые отчёты сохраняются неизменными.

Сохраняйте все попытки. Не выбирайте лучший ответ из нескольких. Повторы обозначаются `--replicate 1`, `--replicate 2` и т. д.; полный повтор содержит все 30 задач. Для каждого сочетания модель/effort используется свой полный набор. Уровень `default` означает effort по умолчанию, `none` — явно отключённый reasoning. Не подменяйте их `low`.

Запишите точный ID модели, маршрут доступа без авторизации, настройки инструментов и ОС/runtime. В `method` уточните системный промпт, таймаут, параллельность, ограничения токенов и политику повторов. Неизвестное называйте неизвестным. Если запрос не завершился, используйте `--transport-error timeout` и пустой файл ответа; это отдельная ошибка транспорта и нулевой балл в полном запуске, а не основание удалить задачу.

Для T-задач предоставьте `--history history.json`: массив настоящих записей доверенного исполнителя инструмента. Формат описан в [протоколе](docs/PROTOCOL.md). Не сообщайте модели содержимое `answers.json`, каталоги или готовые цепочки заранее. Не используйте эталонное решение как ответ модели.

`study submit` без флага отправки показывает отчёт локально. После согласия человека `--publish` создаёт ветку в его fork и pull request в `teo-nex/TeoBench`. Владелец репозитория отправляет в отдельную ветку того же репозитория. CLI не объединяет PR.

Публичными станут ответы, история синтетического lookup, модель, effort, условия, время и оценки. Отчёт не требует аккаунтов провайдеров, API-ключей, cookies, системных логов или домашних путей. Перед отправкой просмотрите файл. Проверка на распространённые форматы секретов помогает отсеять случайные утечки, но не заменяет просмотр.

GitHub проверяет JSON и повторно оценивает ответы базовым оценщиком. Код из PR при этой проверке не выполняется; Python-ответы исполняются ограниченным worker в sandbox. Полный отчёт со старой версией оценщика может быть принят через PR, только если эта версия явно совместима с текущей и все сохранённые оценки подтверждены переоценкой. Исходные ответы и версия оценщика сохраняются; результат проверки указывает текущий оценщик отдельно. CLI не позволяет дописывать или публиковать исторический checkpoint: новые измерения требуют нового ID и текущей версии. Изменения кода и схемы отправляйте отдельными PR. Не объединяйте их с новыми исследованиями.

После принятия отчёт участвует в автоматическом пересчёте `Easy-Bench/statistics/summary.json`. Исторические неполные запуски исключаются из общей статистики. Новые PR должны покрывать весь протокол; 35 пилотных и 42 контрольных ответа хранятся отдельно от основной матрицы через зарезервированные номера повторов и не входят в первичный рейтинг. Точные дубликаты наборов ответов не повышают число исследований. Отдельные условия, маршруты и версии оценщика не смешиваются.

Вклад в задачи, код и отчёты распространяется под MIT. Отправляйте только материалы, которые вправе опубликовать. Отчёты сообщества остаются самоотчётами об использовании модели; переоценка проверяет ответы, а не происхождение inference.
