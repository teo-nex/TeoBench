# TeoBench

[English](README.md) · **Русский**

Открытый набор для проверки reasoning моделей и сбора воспроизводимых исследований сообщества.

Первый уровень — **[Easy-Bench](Easy-Bench/README.md)**: 30 задач из уже проведённого исследования reasoning effort. Тексты, входные данные и эталоны сохранены без изменений. Это небольшой синтетический baseline; более сложные рабочие сценарии пока не добавлены.

| Категория | Задач | Что проверяем |
|---|---:|---|
| Reasoning | 6 | Округление, интервалы, оптимизация, подсчёт вариантов |
| Python | 6 | Функция `solve(data)`, 300 проверок |
| SQL | 6 | SELECT на 72 базах SQLite |
| Данные | 6 | Фильтры, ревизии, дубликаты, недоверенный текст |
| Инструменты | 6 | Последовательность реальных вызовов `lookup` |

## Полное исследование — инструкция агенту

**По умолчанию исследование — 7 моделей × 5 effort × 30 задач = 1050 основных запусков, а не 30 запусков одной модели.** Повтор исходного протокола также включает 35 пилотных и 42 контрольных запуска: всего 1127. Нужны все семь моделей и все пять effort; недоступный маршрут означает BLOCKED, а не сокращение исследования.

Откройте **[инструкцию полного исследования](docs/RUN_FULL_STUDY.md)** и [AGENTS.md](AGENTS.md). Точные модели, effort, задания и фазы зафиксированы в [campaign.json](Easy-Bench/campaign.json). Агент вызывает настроенные модели сам; команды просмотра CLI не запускают инференс.

**Отправьте эту команду агенту, а не в терминал:**

```text
RUN_TEO_BENCH: выполни RUN_RESEARCH.md в https://github.com/teo-nex/TeoBench прямо сейчас. Проведи все 1127 запусков через мои настроенные модели, сохраняй каждую попытку и продолжай до COMPLETE либо конкретного BLOCKED. Не останавливайся на чтении репозитория или выводе плана. Перед публикацией результатов спроси согласие.
```

[Задание на выполнение](RUN_RESEARCH.md) требует реальных модельных вызовов. Режим только для чтения или отсутствие доступа к моделям означает BLOCKED: сам репозиторий не может выдать клиенту эти права.

Новые исследования используют **[изолированный запуск](docs/ISOLATED_INFERENCE.md)**: `study create --execution-profile auto` выбирает установленный Pi, а при его отсутствии — [временный чистый профиль Codex](docs/CODEX_FALLBACK.md). Модель получает фиксированные инструкции без личных настроек, skills и истории. Временный профиль Codex удаляется после каждой попытки, результаты сохраняются. Агент повторяет выбранную команду до завершения кампании. Pi, Codex и старые исследования имеют отдельные отпечатки методики.

## Быстрый старт

Офлайн-проверка работает на Python 3.9+ со стандартной библиотекой; пакеты Python и ключи API для неё не нужны. Запросы к моделям используют установленный Node/Pi или Codex и существующий вход; клиенты автоматически не устанавливаются. Для проверки Python и SQL дополнительно требуется системная изоляция:

- **macOS:** встроенный Seatbelt и Python вне `/Users` и `/Volumes`. При отказе Seatbelt автоматически используется уже работающий локальный Docker с Linux engine. До запросов к моделям выполните `python3 -m teobench doctor --prepare`; при работающем Seatbelt Docker не нужен.
- **Windows 10/11:** обычный Windows Python и работающий [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с Linux engine. Один раз выполните `py -3 -m teobench doctor --prepare`, чтобы получить закреплённый официальный образ Python. Windows CLI не требует Bash, WSL-команд и модуля `resource`.
- **Linux:** [Bubblewrap](https://github.com/containers/bubblewrap) (`bwrap` с поддержкой `--disable-userns`), разрешённые непривилегированные user/network namespaces и интерпретатор, чей реальный исполняемый файл находится в `/usr`. Установите Bubblewrap менеджером пакетов дистрибутива (например, `sudo apt-get install bubblewrap`). Checkout и домашний каталог должны находиться вне `/usr`, `/lib` и `/lib64`.

Linux sandbox открывает только системные каталоги runtime для чтения, скрывает домашний каталог, checkout, временные файлы хоста и `/proc`, изолирует сеть, процессы и окружение. При отсутствии или запрете изоляции оценщик отказывает в запуске; небезопасного fallback нет. На Windows worker запускается в одноразовом Linux-контейнере без каталогов хоста и сети, с корнем только для чтения, непривилегированным пользователем и ограничениями CPU, памяти и процессов. На остальных ОС исполнение Python пока не поддерживается. На Linux при отказе Bubblewrap используется уже настроенный локальный Docker и фиксированный локальный образ Python. Оценщик не скачивает образы и не меняет AppArmor/sysctl. [Требования и выбор режима](docs/PROTOCOL.md).

Для SQL нужен runtime с действующим лимитом памяти SQLite. Если системная SQLite на macOS его не поддерживает, TeoBench переиспользует подходящий установленный Python без скачиваний. Seatbelt не задаёт жёсткий лимит RAM для Python: заведомо враждебные ответы проверяйте на отдельной Linux-машине или в контейнере. [Границы безопасности](SECURITY.md).

```bash
git clone https://github.com/teo-nex/TeoBench.git
cd TeoBench
python3 -m teobench verify
python3 -m teobench list
python3 -m teobench show R01
python3 -m unittest discover -s tests -v
```

В **Windows PowerShell** используйте Python launcher из каталога репозитория:

```powershell
py -3 -m teobench doctor --prepare
py -3 -m teobench verify
py -3 -m teobench campaign plan
py -3 -m unittest discover -s tests -v
```

На **macOS** сначала выполните `python3 -m teobench doctor --prepare`, на **Linux** — `python3 -m teobench doctor`. Подробности: [настройка по ОС](docs/SETUP.md). `doctor` проверяет изоляцию grader; доступ ко всем 35 сочетаниям модель/effort агент проверяет отдельно. Настройка использует установленные инструменты и не меняет безопасность или сеть хоста.

Полученный ответ можно проверить отдельно:

```bash
python3 -m teobench grade R01 --answer answer.txt
```

Все команды работают из корня checkout. Оценщик не вызывает модели. Для выполнения задач подключите свою модель или агента и передавайте ему только вывод `show` и разрешённый `lookup`, без доступа к эталонам.

## Отправить своё исследование

1. Создайте отчёт с точным ID модели, effort и условиями запуска.
2. Сохраняйте каждый ответ, включая ошибки. Один блок — 30 задач для одной модели и effort; полная основная матрица — все 35 таких блоков. Выполните также пилот и контроль по инструкции выше.
3. Проверьте отчёт и просмотрите состав публичных данных.
4. Подтвердите отправку: CLI создаст pull request; автоматического merge нет.

```bash
python3 -m teobench study create --id my-first-study --file local-runs/study.json \
  --access-route 'provider/model endpoint, no credentials' \
  --environment 'macOS arm64; Python 3.12; no extra tools'

python3 -m teobench study record --file local-runs/study.json \
  --task R01 --model exact-model-id --effort high --answer answer.txt

# Повторите record для остальных задач; ошибки и повторы тоже сохраняйте.
python3 -m teobench study validate --file local-runs/study.json
python3 -m teobench study submit --file local-runs/study.json

# После просмотра отчёта и согласия на публичную отправку:
python3 -m teobench study submit --file local-runs/study.json --publish
```

Отправка требует авторизованный [GitHub CLI](https://cli.github.com/). Без `--publish` команда только показывает предварительный просмотр и не обращается к GitHub. Подробности: [CONTRIBUTING.md](CONTRIBUTING.md) и [протокол](docs/PROTOCOL.md).

## Исследования и статистика

- [Принятые отчёты](Easy-Bench/studies): ответы, оценки и условия запуска в едином JSON-формате.
- [Сводная статистика](Easy-Bench/statistics/summary.json): пересчитывается после принятия отчётов; отдельные группы для разных моделей, effort, маршрутов, окружений и версий оценщика.
- [Первое исследование, 3 ноября 2026](Easy-Bench/research-2026-11-03/README.md): 7 моделей × 30 задач × 5 effort = 1050 основных ответов; после исправления оценщика — **991/1050**.

GitHub проверяет структуру отчётов и заново оценивает ответы доверенным кодом базовой ветки. Только полные запуски попадают в сводку; точные копии наборов ответов исключаются. Идентичность серверной модели, честность истории инструментов и отсутствие доступа к эталонам остаются заявлениями автора исследования. Эти данные не являются независимой аттестацией провайдера или репрезентативной выборкой всех пользователей.

Эталоны опубликованы для воспроизводимости: Easy-Bench больше не скрытый holdout. Внутренние исходные метки `easy/medium/hard` сохранены, но весь старый набор относится к уровню TeoBench **Easy**. [Происхождение и контрольные суммы](Easy-Bench/tasks/PROVENANCE.json). Лицензия — [MIT](LICENSE).
